# SmartApp

macOS 菜单栏上下文采集器。v0.4 记录用户先后到达的前台应用、窗口、网页、Finder／QSpace Pro 目录和工作窗口提供的文件位置，为下一目标推荐积累数据。默认推荐菜单提供应用、窗口和网页；目录与具体文件通过同一菜单中的 FileRecall 入口查找。另有独立剪贴板历史，供用户查看和重新复制。到达采集与操作方式无关，不记录键盘、快捷键、点击、滚动、鼠标轨迹或后台状态。

## 开始使用

运行需要 macOS 14+，构建需要 Xcode 26+（Swift 6.2+，用于原生 Liquid Glass API）。目标采集和普通推荐使用原生 Swift；FileRecall 目录判断复用本机已经安装的 Kev Python 环境与模型缓存，不下载模型、不调用云服务。环境要求见 [剪贴板与 FileRecall](docs/CLIPBOARD_AND_FILERECALL.md)。

```sh
./scripts/install-app.sh
```

安装位置：`~/Applications/SmartApp.app`。在面板点击「开始采集」，关闭面板后继续在后台运行；常规启动默认暂停。

采集采用统一目标准入策略：普通独立应用、合格工作窗口、允许的浏览器页面、已观察到的 Finder／QSpace Pro 目录和手动添加的本地目标才能进入目标库。安全辅助组件、后台 helper、临时浮层与未知对象会被过滤；特殊工具需具有可确认的独立工作窗口。观察中断会作废在途回调。规则与数据兼容说明见 [上下文数据](docs/DATASET.md#目标准入策略)。

- **应用切换**：无需输入监控权限。只记录确认的前台激活和其前台目的地；不建立运行应用或后台窗口清单。
- **窗口**：开启 Privacy & Security → **Device Control and Data Access**（较旧系统为 Accessibility）。前台约每 0.5 秒观察一次，只读取当前聚焦窗口。
- **浏览器**：Chrome、Edge、Brave 使用本地浏览器扩展，以事件驱动采集 macOS 前台浏览器的聚焦普通窗口中**唯一活动标签页**、完整 HTTP(S) URL、前台到达和稳定停留。扩展和原生端都不读取、传输或持久化后台窗口/标签页。不再定时扫描浏览器，也不再需要浏览器 Automation 授权。首次需安装扩展与 Native Messaging 接入，见 [安装与协议](docs/BROWSER_EXTENSION.md)。无痕模式不允许启用扩展；其他浏览器仍可采集应用/通用窗口。
- **Finder 与 QSpace Pro 目录**：各自授予自动化权限后，自动记录实际显露的真实目录，无需提前登记。Finder 只读取前台窗口；QSpace Pro 只读取前台窗口的活动窗格 `root item.urlstr`。两者前台约每 0.5 秒观察，优先使用随应用签名的轻量读取进程，失败时回退原脚本；离开文件管理器或暂停采集即关闭该进程。不补充后台窗口或窗格；保存完整 `file://` 路径，不读取选择项或扫描目录内容。搜索、最近使用、虚拟视图或不是实际目录的位置回退到窗口。
- **本地文件**：支持文档定位的前台工作窗口自动记录实际显露的文件地址，无须手动添加；不读取文件正文。仍可在「本地目标与导出 → 添加快捷目标…」补充已知目标，登记本身不视为到达。
- **推荐目标菜单**：晃动鼠标、双击同一侧 Command（⌘）或使用菜单栏入口，应用、窗口和网页推荐以对应真实图标从鼠标右上方起，按固定间距顺时针沿圆弧展开；数量按分差门槛变化，暂时最多 6 项，不补齐到 4 项，少量选项不铺满整圈。网页和窗口附类型角标。悬停查看名称，图标随鼠标相对位置轻微偏移、倾斜并移动高光，移开后平滑回位；文字和点击区域保持稳定。点击打开，按 Esc、点击中央或空白处关闭。未选择即关闭的整次菜单会话只存在于内存，不进入行为数据，也不会影响随后自然导航。靠近屏幕边缘自动避让。macOS 26+ 使用原生 Liquid Glass，旧系统使用磨砂材质，并适配降低透明度、增强对比度及减少动态效果。鼠标方向变化只短暂留在内存。当前优先使用个人历史训练的路径小模型，结合当前前台目标、已确认停留、观察质量及不同时间范围的目标与上级使用次数排序；上级网页只从已确认页面的完整 URL 临时推导，执行前再次核对；目录和文件不进入默认推荐。模型不可用时沿用已有的历史最近访问排序，最多 6 项。

两种手势在开始采集后生效，可在「采集设置 → 唤出方式」分别开关，修改自动保存。灵敏度越高越容易唤出。点击「开始示范」，等待 1 秒后，在接下来的 5 秒内左右快速来回晃动，至少转向 4 次；成功后显示单程幅度与用时，并自动应用个人阈值。可继续拖动滑块微调，或恢复默认灵敏度。示范可在暂停采集时进行，不会打开目标菜单；取消、超时或关闭设置面板均保留原设置。只将一次示范的幅度、用时和时间保存在应用偏好中，不保存轨迹，也不进入训练数据。

双击 Command 要求两次独立按下并松开同一侧按键，每次按住不超过 0.25 秒，两次之间不超过 0.35 秒；普通组合键、其他修饰键、点击和滚动会取消识别。全局识别需要辅助功能权限，使用与窗口观察相同的授权。按键事件只在内存中判断是否取消手势，不读取输入正文或记录键值；原有快捷键继续传递给当前应用。鼠标拖拽不唤出菜单，晃动唤出有 3 秒冷却时间。

输入事件完全不落盘。网页完整 URL 和目录路径直接保存在 `locator` 文本字段中，训练导出保留这些地址及其语义；URL 仅去除内嵌账号密码并做协议、主机、默认端口等语法归一化，不删除查询参数或片段。到达采集不读取页面正文或截图；只有主动进入 FileRecall 才临时读取原聚焦窗口内容，关闭后清除，不进入行为训练。页面和目录都有稳定的本地密钥 ID：已有入口时切回原网页标签、Finder 窗口或 QSpace Pro 窗格；入口关闭或已导航时按保存地址重新打开（网页使用默认浏览器，QSpace Pro 目录优先交给 QSpace Pro）。`identity-v2.key` 不包含在导出中。旧版只存 ID 的历史网页无法反推地址，再次观察后会补全定位。

采集面板显示来源状态和实际观察。窗口支持、轮询延迟、系统暂停等会影响覆盖；打开应用不代表正在播放或录音，前台停留也不证明用户注意力。排除应用/网站、安全输入、锁屏、暂停和采集缺口单独记录。

## 剪贴板与目录查找

推荐菜单鼠标下方的固定「目录与文件」按钮进入 FileRecall，中央右侧的剪贴板图标打开历史；两者不占用推荐名额。也可在菜单栏或主面板查看剪贴板，首次点击「开始记录」后才保存内容。支持搜索、收藏、预览、重新复制和删除；历史与到达数据分别保存，不进入行为导出或训练。启动已有内容的原更新时间标为未知，不自动作为刚复制的依据。

FileRecall 仅在主动进入时结合可读的当前工作窗口与本次剪贴板信息，在已确认前台到达的目录和文件路径中查找；目录可展开历史观察到的文件。浏览器需重新加载 0.4 版扩展以核对当前普通活动页。普通应用／窗口／网页推荐暂未接入剪贴板内容理解。用法、模型环境和边界见 [剪贴板与 FileRecall](docs/CLIPBOARD_AND_FILERECALL.md)。

## 数据与导出

新数据和旧轨迹数据分开保存：

```text
~/Library/Application Support/SmartApp/context-v2.sqlite
~/Library/Application Support/SmartApp/events.sqlite       # 原 v1 数据，保持不变
```

当前库使用 SQLite WAL。有界内存批次在达到 **128 条事件**、**1 MiB** 或首条等待 **10 秒** 后提交；会话开始/结束、观察边界、导出和正常退出强制落盘。只有超过 1,024 条或 16 MiB 的未完成写入才会暂停采集，避免短暂 I/O 或统计读取被误判为“写入积压”。数据库本体、WAL 与 SHM 合计达到 2 GB 后暂停。数据保留到用户自行归档，不按推荐用的五分钟上下文自动删除；崩溃仍可能丢失尚未提交的当前小批次。数据库未另加应用层加密。

目录用途、命名、权限和迁移约定见 [数据目录规范](docs/DATA_DIRECTORIES.md)。日常归档可运行 `./scripts/export-data.sh`，在数据根目录的 `exports/context-v2/<UTC时间>-<UUID>/` 创建独立快照及校验值。

```sh
./build/smartapp-cli status
./build/smartapp-cli recent
./build/smartapp-cli export --output /absolute/path/to/new-dataset
./build/smartapp-cli rebuild-foreground --output /absolute/path/to/new-context-v2.sqlite
./build/smartapp-cli status --database "$HOME/Library/Application Support/SmartApp/events.sqlite"
```

`rebuild-foreground` 只读取输入库，并在新路径生成前台-only 标准库：仅迁入完整、明确声明当前隐私策略的会话；旧库存、候选、后台状态及其引用不会进入输出。它不会替换运行中的数据库；替换前必须先正常停止应用、生成可验证备份并验证新库，详细流程见 [数据目录规范](docs/DATA_DIRECTORIES.md#前台-only-重建与切换)。

导出新目录，不覆盖现有目录：

- `events.jsonl`：按写入顺序保存完整上下文事件，包含来源、时钟、会话内顺序。
- `target-history.jsonl`：目标信息的历史变更；不能用最新目标状态倒填历史样本。
- `navigation-samples.jsonl`：观察到的前台目标状态为锚点，引用此前短期/较长前台活动历史，再关联后续 30 秒的多步结果；新 v4 样本不含后台库存引用。
- `manifest.json`：版本、统计和覆盖限制。

观察不完整的样本保留 `incomplete` 和原因，不猜测唯一最终目的地，不生成 `__stay__`。实际选择、执行结果通过 `decisionID` 关联，使用冻结的决策前输入；推荐后的导航标记为相关来源。当前序列样本由目标变化生成，推荐决策本身的训练样本可从原始日志单独构造。按会话/时间划分训练与验证数据，不随机拆散重叠序列。

## 权限与开发

应用使用固定的本地自签名身份 `SmartApp Local Release`。首次在本机配置时运行一次：

```sh
./scripts/create-local-signing-identity.sh
./scripts/install-app.sh
```

证书和私钥存于当前用户的登录钥匙串，证书有效期为十年，只被信任用于代码签名。此后 `./scripts/install-app.sh` 始终使用同一证书、`local.herh.SmartApp` Bundle ID 和 `~/Applications/SmartApp.app` 安装路径；安装前会备份旧包，再原地同步新包并校验指定要求，不会把活动安装包改名。经明确同意在更新后继续采集时可用 `./scripts/install-app.sh --collect`；普通安装仍按默认暂停采集。不要删除、重建或改名该钥匙串身份，也不要把构建退回临时 ad-hoc 签名，否则 macOS 可能要求重新授权。首次从旧的临时签名迁移到此身份时，辅助功能等权限可能需要重新确认一次。若需要分发给其他 Mac，应改用 Apple Developer ID 签名。

若开关开启但应用仍显示未授权，确认 `permission-status.json` 中的 PID 和 `bundlePath` 对应当前运行的 `~/Applications/SmartApp.app`；不要因旧版诊断字段 `inputMonitoring=false` 判定采集失败：v0.2 不使用输入事件 tap。

`permission-status.json` 由实际应用写出，诊断应确认 PID 和路径仍对应当前进程。浏览器/窗口连接状态以面板与 `source.status` 事件为准。

```sh
swift test
./scripts/build-app.sh release
```

构建产物位于 `build/SmartApp.app`、`build/smartapp-cli`。常规安装会备份旧应用；旧数据不会迁移进新数据集。项目保留 v1 的读取和导出代码，仅用于旧数据兼容，v0.2 采集器不再调用输入采集或 v1 样本生成逻辑。

详细字段见 [数据格式](docs/DATASET.md)，设计见 [上下文推荐方案](docs/NEXT_APP_DESIGN.md)，实测见 [v2 验证记录](docs/COLLECTION_V2_VALIDATION.md)，旧格式见 [v1 文档](docs/LEGACY_DATASET_V1.md)。

### 在线推荐模型

实际应用只运行 `shared-online-path-mlp-v1` 一套在线学习模型。个人历史训练权重与后续更新保存在数据目录的 `models/`，应用内用原生 Swift 计算，不依赖运行中的 Python。输入只来自已确认的前台到达：当前目标及其所属应用、发生时间、已确认停留、来源质量，以及五分钟、一小时、一天和长期的直接/上级路径使用次数。网页和本地目录的上级入口根据已知完整定位符临时生成；推荐候选只留在内存，不写回采集库，也不读取后台库存。模型输出是排序分数，不是已校准的概率。只有当前可打开的入口会进菜单；不可用入口会由其他历史目标补位。

新模型按真实到达只更新一次：完整观察使用已确认的第一步，不完整观察仅补用已确认的第一步；严格配对的旧版短暂停顿与明确排除范围可在对应条件成立后接续，断开期间不补造目标或停留。预测当时的输入保持冻结，未来才知道的间隔不进入此前输入。模型权重与目标身份密钥绑定，更新状态单独保存；版本或密钥不匹配、权重缺失或训练截止事件不在本地历史时，保留模型文件并报告不可用；菜单沿用已有的历史最近访问排序，不启动另一套学习模型。旧 `semantic-cross-entropy-v3` 及更早版本文件仅作为历史备份保留，应用不再加载、迁移、训练、推荐或保存它们。完整历史拟合包含先前测试时段，不能把旧测试成绩当作这份最终权重的新测试成绩。

当前运行流程复用未变化的路径、目标标识和层级计算。各时间范围的频率通过准确的累计时间索引查询，不再每次扫描全部到达；索引保留完整历史，电脑时间调整时仍按原规则排除尚晚于截点的记录。冻结训练输入按固定字段顺序存放，共用不变的路径信息；反馈处理完且没有在途样本或配对边界再引用后立即释放。学习积压只记录最新已提交数据库位置，用独立只读连接逐条处理，不在队列里保留事件批次。完整采集数据、观察频率和学习字段保持原样，没有新增历史截断、候选数量或时间限制。

同历史回放、测试和安装证据见 [内存优化验证](docs/MEMORY_OPTIMIZATION.md)。

[分差校准与动态数量算法](docs/SCORE_MARGIN_CONFORMAL.md)已接入当前模型及菜单，漏选目标为 10%，暂时最多 6 项。校准使用冻结预测之后新确认的合法到达，菜单展示与关闭不新增学习样本；只把分差、版本和汇总计数随当前模型状态保存。初次接入、尚无校准样本时保留最多 6 项，再随新行为调整。10% 是调整目标，不是已测得的实际漏选率或单次置信度；六项上限造成的漏选另计。

可用 `smartapp-cli validate-model --input <私有校验数据> --output <新私有报告>` 校验旧语义模型；新路径模型的跨语言输入与排序对照保存在权限受限的个人训练 run。真实行为及完整定位符不进入源码报告。
