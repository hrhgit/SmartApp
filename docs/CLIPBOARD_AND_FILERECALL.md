# 剪贴板历史与 FileRecall（0.4.0 / build 14）

本次按已确认顺序接入：先提供独立剪贴板管理，再让 FileRecall 在用户主动查找时结合剪贴板。普通应用、窗口和网页推荐读取剪贴板内容的效果验证留在下一阶段。

## 入口与操作

原晃动鼠标、双击同侧 Command 和菜单栏入口保持原用法。唤出推荐菜单后，鼠标下方固定的「目录与文件」按钮进入 FileRecall；中央右侧的剪贴板图标打开历史。两个工具不占用推荐名额。默认弧线菜单只提供应用、窗口和网页，本地目录与具体文件均从这里移出。

剪贴板也可从菜单栏「查看剪贴板历史」或主面板「剪贴板」打开。首次需要点击「开始记录」，默认关闭；开启状态保存在独立偏好中，之后启动继续记录，点击「暂停记录」则停止。目标到达采集与剪贴板记录分别控制。

历史支持文字、链接、图片、文件引用及原富文本格式的保存、查看、搜索、收藏、重新复制、删除和清空。文件引用仅保存地址，不打开对应文件正文。图片可预览及重新复制；当前目录模型只接收文字和文件引用。列表每页显示 100 条，可以继续加载；分页不删除历史，也不截短存储内容。文件承诺指当前支持的系统格式，应用私有的未支持格式不会保存。

在历史中选中一条，可点击「用这条查找目录」。需要先在工作窗口唤出菜单进入剪贴板，这样本次查找知道要结合哪个工作窗口；直接在 SmartApp 主面板操作时会显示返回工作窗口的说明。仅浏览历史不会调用 AI。

FileRecall 先显示相关目录，目录下可展开此前在前台确认到达过的文件；这里的文件列表来自到达记录，不是读取目录内容。点击路径或文件打开；上下键选择目录，回车打开，Command+C 复制路径，Esc 关闭。补充项目名或任务后可重新查找，沿用同一次冻结输入。模型当前排序的是目录，具体文件供用户展开选择，不宣称已经做了独立文件排序。

## 更新时间与使用情况

记录的是系统剪贴板版本发生变化后被观察到的时间。它不证明某次具体 Copy 操作，也不知道内容有没有在其他应用成功粘贴或使用。

启动、手动重新开始或恢复观察时，已有内容不能成为「刚复制」的自动依据。启动时保存的内容标为原更新时间未知；暂停、锁屏、休眠、安全输入或排除应用期间清除自动依据，恢复后的当前版本先作新的基线，只有此后观察到的更新才会自动提供给 FileRecall。密码管理器标记为隐蔽／临时的内容不读取。

本次请求冻结当前条目及观察到更新距请求多久；没有新增任意过期时限。模型输入明确说明时间不证明内容仍有关或尚未使用。旧历史只有用户主动选中才用于本次查找，未知原更新时间仍保留；不会自动把全部历史送给模型。

## 当前窗口与路径依据

唤出菜单时只保存原聚焦窗口的临时引用；点击 FileRecall 后才通过辅助功能读取该窗口的可读内容。读取失败、内容为空、聚焦窗口变化或当前页面无法核对时明确停止，不改用旧内容、截图或标题继续推荐。安全文字框不读取。

浏览器查找目前支持装有 0.4 版扩展的 Chrome、Edge、Brave。点击查找后临时核对唯一当前普通活动页及完整 URL，不读取其他标签或窗口。扩展先读聚焦窗口基本属性，再单独查询其中的活动标签，禁止 `populate:true` 获取全窗口标签。无痕窗口、非网页、已排除网站和失去前台资格的页面均停止。辅助功能内容的 URL 还须与此次核对的页面一致；读取期间导航也会停止。Safari、Firefox 等暂未接入这一核对，不会用未核对页面内容运行模型。

浏览器核对消息不进入前台到达事件或训练。普通浏览器采集仍是原事件驱动流程；新扩展只在明确查找请求下增加这次临时核对。更新后按 [浏览器安装说明](BROWSER_EXTENSION.md) 安装副本并在扩展页面重新加载。

目录候选由 SmartApp 已确认的前台目录／文件到达临时推导；单独登记目标、目录扫描、后台库存或旧库存会话都不会充作到达。文件可为其直接父目录提供派生路径支持，但不增加虚构的父目录到达。补全记录不重复计数，后来的定位信息不倒填到较早的截点。本次未导入旧 FileRecall 的历史库，也未迁入它的 Terminal、VS Code 等独立采集入口。

## 模型与数据

复用 FileRecall 原有 `stat-lexical@32` 目录候选方法，再由本地 `jaredpalmer/kev-0.8b` 比较。32 是沿用的既有候选方法，不是新增的正文截短。模型概率仅表示本次选项比较，不是实测准确率。

本机需已有以下运行环境与缓存：

```text
~/Library/Application Support/FileRecall/kev/.venv/bin/python
~/Library/Application Support/FileRecall/kev/
~/Library/Application Support/FileRecall/model-cache/
```

SmartApp 包内的 `KevSmartAppServer.py` 在自己的子进程中启用完整输入校验、关闭内容缓存、禁止下载。它不改写共享 Kev 源码或模型文件。模型处理能力不足时返回明确错误，不静默截短后继续推荐。服务只绑定 `127.0.0.1:8009`，只使用当前 SmartApp 自己启动且有完整输入标记的服务；关闭查找时结束自己的模型服务，下一次等待旧进程退出后重新启动，不关闭其他应用拥有的进程。缺少环境、端口被占用或模型退出时显示原因。

剪贴板存于独立的 `SmartApp/clipboard/history-v1.sqlite`，目录权限 0700、数据库 0600。删除与清空启用 SQLite 安全删除并清理事务日志；这不承诺抹去外部备份或存储介质的旧块。历史不进入 `context-v2.sqlite`、目标到达统计、在线模型重放、行为导出或训练；没有新增自动保留上限。

页面正文、请求中的剪贴板内容、补充描述和候选只在请求内使用，不写入推荐日志；关闭、返回或换窗口后清除控制器中的本次内容并取消待处理请求。实际点击打开的路径及执行结果可以作为已有的选择反馈保留，随后真实到达仍由普通采集入口确认。

在线学习继续只运行原来的路径模型，并保留本地到达作为行为上下文及学习结果。普通菜单的分差调整只核对应用／窗口／网页结果：本地到达不算普通菜单漏选。范围版本为 `app-window-page-v1`，旧分差调整状态因范围变更重新积累，有效模型权重保留。

验证范围与未验证部分见 [接入验证](CLIPBOARD_AND_FILERECALL_VALIDATION.md)。
