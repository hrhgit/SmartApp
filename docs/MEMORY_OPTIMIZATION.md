# 当前在线模型的内存优化验证

2026-10-04，安装版本 13。实际应用仍只运行 `shared-online-path-mlp-v1`，模型参数、输入字段、反馈规则及原始采集边界保持原样。

## 改动

- 复用未变化的目标路径、父级层次和标识计算；目标实际被重新确认或定位符变化后刷新，冻结的旧输入不跟着改变。
- 用准确的累计时间索引代替逐次扫描全部到达。索引按路径与直接到达分别保存紧凑时间值，通过区间查询取得五分钟、一小时、一天和长期次数；窗口边界、电脑时间回拨和当前到达不计入自身此前频率的规则保持一致。历史未被截断。
- 训练行按固定字段顺序存放，共用不变的路径信息。仍接受原来的字段字典接口，字段缺失、不符及非有限值继续拒绝。十六进制标识格式保持一致，避免每个字节都创建临时 Foundation 字符串。
- 在途样本、已确认第一步及允许接续的配对边界完成后释放结果元数据和冻结输入；移除会挤掉仍有效输入的固定 512 条上限及结果元数据 8,192 条上限。原有反馈去重规则不变。
- 学习队列只保留最新已提交数据库位置，由独立只读连接顺序处理其前面的未消费记录；重复或较早的位置不重复学习。读取每条记录、计算和保存后的临时对象及时释放。

## 相同历史对照

使用 SQLite 在线备份得到同一份私有快照，共 45,912 条事件。两版使用相同初始模型参数、事件顺序和学习输入，只为数据库位置 43,000 起的最后 2,913 条事件生成预测/冻结输入，其前面的历史仍用于恢复目标与全部频率。真实定位符、模型参数与快照仅保存在数据目录的权限受限训练 run，不进入源码报告；没有导出或保存独立候选名单。

检查 412 个可生成输入的截点、合计 423,243 行候选输入：全部数值字段、分类字段、路径、动作身份及临时定位符的整体摘要一致。抽查 4 个截点的全部输入向量与排序分数，整体摘要一致。成熟反馈顺序及 278 次增量学习后的完整模型参数和更新状态摘要一致。这是执行行为一致性检查，没有重新评定模型命中率。

| 相同回放工作量，原生 release 进程 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 峰值常驻内存（RSS，十进制 MB） | 223.8 | 144.4 |
| 回放、生成冻结输入和学习耗时（秒） | 246.7 | 52.3 |
| 实际学习更新数 | 278 | 278 |

内存峰值减少约 35.5%，这一回放的处理时间缩短约 78.8%。计时包括全历史读取、输入生成与增量学习，不含应用界面、采集来源、菜单排序或输入摘要的逐行编码；两版各运行一次，现场其他负载会影响耗时。包含逐行输入编码和分数摘要的另一项对照也通过，但不把其耗时当作生产处理延迟。

## 回归与安装

`swift test` 共 179 项通过：SmartApp 53 项，IntentCore 126 项。新增验证覆盖精确窗口和时钟调整、已确认元数据变化后刷新路径缓存、读连接固定提交上界时写连接继续工作，以及同一会话 520 次连续目标切换。最后一项保留 519 个有效第一步更新；2,000 轮最新/旧提交位置通知没有造成遗漏或重复。

release 构建和固定本地签名检查通过，安装至既定位置，安装二进制与构建结果一致。更新前正常退出并备份数据库、身份密钥、目标登记与模型；备份 46,327 条事件，SQLite 完整性检查通过，模型训练边界存在。更新后 `activeLearningModels=1`、模型就绪、错误为空，更新总步数仍为 2,684，未重复学习旧记录；辅助功能授权仍有效，采集已恢复。随后实际记录继续写入，确认的前台上下文为 `foreground_only`，来源出现成功确认。后续实际使用还完成至少 10 次新的学习更新，仍只有一个模型且没有报告错误。

## 仍有的增长与验证范围

精确时间索引仍随已确认到达缓慢增长，每个路径/直接计数记录只保留一个 64 位时间值；目标目录及路径缓存也会随不同目标的数量增长。尚未成熟的反馈可以暂时增加冻结输入数量，完成后按依赖释放。没有以候选数、历史时长或新超时限制换取省内存。

回放进程的 RSS 不等同于活动监视器显示的整应用内存。刚重启的应用、运行了数小时的应用和回放进程的数字不能直接作同条件比较；系统压缩、共享页、临时分配及内存压力也会改变显示值。已证明这份历史工作量下的峰值和重复计算下降，并验证当前安装版继续采集；尚未完成数小时/数天持续运行验证，不能据此保证整应用内存永不增长。
