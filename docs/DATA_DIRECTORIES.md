# 数据目录规范

SmartApp 的用户数据根目录固定为 `~/Library/Application Support/SmartApp/`。`~` 指运行应用的 macOS 用户主目录；代码使用系统 Application Support 路径，不写死某个用户名。源码、`.app` 安装包、`build/` 和 `/tmp` 不作为长期采集数据的位置。

## 当前布局与预留用途

```text
~/Library/Application Support/SmartApp/
├── context-v2.sqlite               # 当前前台到达原始事件
├── context-v2.sqlite-wal           # SQLite 管理的事务文件，可能不存在
├── context-v2.sqlite-shm           # SQLite 管理的共享状态，可能不存在
├── clipboard/
│   ├── history-v1.sqlite           # 独立剪贴板内容历史，不进入行为导出或训练
│   └── history-v1.sqlite-{wal,shm} # SQLite 管理；删除／清空后清理事务日志
├── identity-v2.key                 # 页面身份密钥；与原始数据一起保留
├── registered-targets.json         # 可选手动快捷目标；自动网页/目录直接保存在数据库
├── events.sqlite                  # v1 旧轨迹数据，保留用于兼容读取
├── events.sqlite-{wal,shm}         # 旧数据库可能遗留的伴随文件
├── permission-status.json          # 当前应用写出的运行诊断，不是训练数据
├── runtime/browser-bridge-v1/      # 0700；endpoint.json 为 0600 的临时端口/令牌，不导出
├── integrations/browser-v1/       # 扩展安装副本、native host 启动器及可恢复安装备份，无行为日志
├── exports/
│   └── context-v2/
│       └── <UTC时间>-<UUID>/       # 每次导出一个新快照，禁止覆盖已有快照
├── backups/                       # state-v3-<UTC>-<UUID>/：数据库/身份密钥及登记文件备份
├── training/                      # 按 run ID 分隔的分析、迁移与训练产物
│   └── current-state-dataset.json  # 最近一次验证通过的 v3 迁移产物指针
└── models/
    ├── semantic-statistics-hard-kind-v1/
    │   ├── seed.json              # 历史种子，保留不变
    │   └── state.json             # v1 模型，升级后保留用于回滚
    ├── semantic-navigation-hierarchy-v2/
    │   └── state.json             # 旧模型归档，不再加载或更新
    ├── semantic-cross-entropy-v3/
    │   └── state.json             # 旧模型归档，不再加载、迁移或更新
    └── shared-online-path-mlp-v1/
        ├── weights.json           # 私有历史训练权重，作为可恢复的起点
        └── state.json             # 反馈成熟后继续学习的权重、更新及分差校准状态
```

`exports/` 由规范导出命令按需创建。`backups/`、`training/` 用于状态迁移与研究。实际应用只运行 `shared-online-path-mlp-v1` 一套在线学习模型，其目录为 `0700`、文件为 `0600`；优先读取 `state.json`，否则读取 `weights.json`。权重包含身份密钥指纹、训练截止事件及继续学习状态。应用只读逐条重放已确认的前台历史以恢复预测输入，只在训练截止事件之后学习，并按数据库已提交位置避免重复处理。反馈成熟后仅保存这套模型的新权重，不把输入候选写入原始库。版本、密钥或训练截止事件不匹配时保留原文件并报告不可用，菜单使用已有的历史最近访问排序。

在线学习使用独立只读连接和已提交位置，重复或较早的位置不会重复学习，最新位置可覆盖此前尚未处理的所有提交。队列只保留一个待处理位置，不保留原始事件批次；每条读取、计算后的临时对象及时释放。完整历史保留在原库，内存中的频率索引只存各路径/直接到达的紧凑时间值，长期次数与短期窗口均不截断；已冻结输入与结果元数据按在途样本及允许接续的边界依赖释放。索引和候选缓存不新增采集写入或导出字段，也不另行保存候选。

`state.json` 的可选 `scoreMarginCalibration` 字段与权重、训练截止事件在同一次原子写入中保存。它只包含 `score-margin-state-v1` 格式版本、模型/输入/匹配规则版本、10% 漏选目标、调整速度、内部调整值、已完成反馈的排序分差及汇总计数、当前六项上限；正确入口缺失的无穷分差编码为 `null`。不保存动作、预测或结果的身份，不保存 URL/路径、分数列表、菜单清单及待确认预测。没有该字段的旧权重仍可读取，校准从模型训练截止之后的新冻结预测开始；重启后不重建旧预测的分数。校准状态本身不合法或版本/策略不匹配时保留有效模型，重新积累校准行为并报告原因。

旧 `semantic-cross-entropy-v3` 及更早模型目录保留为历史恢复资料，应用不再读取、迁移、学习、推荐或保存它们。旧模型实现仅供离线研究和历史校验使用。`runtime/recommendation-status.json` 只报告当前模型版本、是否就绪、实际运行的学习模型数量、更新次数、动态菜单上限/漏选目标、校准样本数、正确入口缺失数、自然到达预测的门槛覆盖/六项覆盖/上限漏选汇总及错误，不包含旧模型学习记录统计、预测输入、推荐列表或后台库存。这些汇总不是实际菜单展示次数或实际菜单覆盖率。迁移仍先使用 SQLite 在线备份 API 生成一致数据库并检查完整性，再从备份派生新样本，保留历史原始数据和不可变导出。

当前数据库、密钥和诊断文件继续使用现有路径；根目录内的少量固定文件是稳定的应用存储接口。将来新增批量产物必须进入对应子目录，不能继续向根目录堆放带日期的文件。应用偏好通过 macOS UserDefaults 管理，归属 `local.herh.SmartApp`，不混入训练数据。

唤出偏好沿用 `shakeEnabledV2`，新增 `doubleCommandEnabledV1`、`shakeSensitivityV1` 与 `shakeCalibrationV1`。校准仅保存单程幅度中位数、4 次转向用时和示范时间；仅保留最近一次成功示范，取消或失败不覆盖。恢复默认灵敏度会清除校准参数。鼠标坐标、轨迹、Command 按键时序以及用于排除组合键的瞬时事件均不持久化，不进入原始上下文数据库或导出。

剪贴板采用独立的 `ClipboardHistoryStore`，根目录 `clipboard/` 为 0700、数据库为 0600。保存观察到更新时间及未知原更新时间标记、支持格式的完整内容、搜索文字与收藏状态，不保留来源应用身份或粘贴成功推断。每页显示 100 条只是读取分页，不设置保留条数或正文截短。剪贴板启用状态保存在 `clipboardRecordingEnabledV1`（默认 false）；开启后重启继续记录，暂停后不再自动开启。标准前台导出与数据库重建不读取这个库，个人完整应用备份需另外保留它。

FileRecall 请求的窗口正文、补充描述和候选不落盘。包内 `KevSmartAppServer.py` 复用已有 `~/Library/Application Support/FileRecall/kev/` Python 环境和 `FileRecall/model-cache/`，关闭请求内容缓存并拒绝静默截短；不修改旧 FileRecall 历史或共享模型文件。新菜单范围版本为 `app-window-page-v1`，只调整分差校准的匹配范围；有效在线模型权重及目录／文件到达保留。详见 [剪贴板与 FileRecall](CLIPBOARD_AND_FILERECALL.md)。

## 导出与命名

项目根目录执行：

```sh
./scripts/export-data.sh
```

输出示例：`exports/context-v2/20260918T070000Z-<UUID>/`。目录时间使用 UTC，避免跨时区与夏令时歧义；UUID 防止并发或同秒导出冲突。应用版本不替代数据格式版本，v1 与 v2 不合并。

快照内包含：

- `events.jsonl`：原始事件。
- `target-history.jsonl`：目标历史更新。
- `navigation-samples.jsonl`：可重算的序列样本。
- `manifest.json`：格式版本、导出时间、数量、观察窗口与限制。
- `SHA256SUMS`：规范导出脚本生成的上述四个文件校验值。

在快照目录执行 `shasum -a 256 -c SHA256SUMS` 可检查内容是否变化。快照按约定保持不可变，并未设置文件系统只读；需要改特征、样本规则或清洗数据时创建新的训练 run，不修改原始快照。每个训练 run 应记录输入快照及校验值、处理规则版本、时间划分、排除会话、参数、代码版本和模型版本，使结果可追溯；训练功能实现时落实这些文件。

当前面板「导出数据」仍允许选择父文件夹，CLI 也支持显式 `--output`；它们创建新快照且不覆盖已有目录，但不会自动生成脚本附加的 `SHA256SUMS`。日常归档优先用上述规范命令。导出包含所有已记录会话，不自动把验收数据排除；验收会话见 [验证记录](COLLECTION_V2_VALIDATION.md)。

## 写入、权限与备份

### 前台-only 重建与切换

当需要从含旧库存、候选或后台状态的历史库切换到当前隐私边界时，不能在活动 SQLite 文件上就地删字段。按以下顺序执行：

1. 正常停止 SmartApp，确认没有该运行库的写入者。
2. 用 SQLite 在线备份 API 生成新、可验证的备份；备份包含 WAL 的已提交内容。
3. 对备份运行 `smartapp-cli rebuild-foreground --database BACKUP --output NEW_DATABASE`。该命令只写新的输出路径，并报告迁入/剔除会话与事件数。
4. 用只读状态命令和 `PRAGMA quick_check` 验证输出；确认没有库存、候选、后台状态或其引用后，才将旧数据库及其侧车文件移动到备份目录，再把新库切换为 `context-v2.sqlite`。
5. 保留 `identity-v2.key`、`registered-targets.json` 和用户偏好；将依赖旧历史的 `models/*/state.json`、`seed.json` 与运行状态一并归档，让应用从新库重新建立派生模型。

重建器只迁入完整、显式声明 `foreground_destinations_only_no_background_state` 的会话。旧策略、未正常结束会话和非目标辅助记录不会进入新库；如果一个声称合规的会话含有禁止的后台字段，重建必须失败并保留原库供审计。

以下 v1/v2/v3 模型迁移说明仅记录历史实现，不再由当前应用启动流程执行。离线兼容校验不得因此恢复旧模型的运行或学习。

历史标签缺少结果定位符时，只在从 v1 迁移时从当前已经准入的目标目录补充结果元数据，记录 `metadataEnrichedAtMs` 和 `migratedFromVersion`；这不修改早先输入，也不代表早先已知这些元数据。离线时间回放必须使用原结果成熟时的元数据，不能使用此迁移后的目录回填。v1/v2 文件和原始数据库不改写；仅向 v3 目录原子写入派生状态，权限保持 `0700/0600`。

ChatGPT 普通对话和起始页共享服务层监督，完整 URL 仍保存在原结果元数据。服务输出在菜单/执行时解析到已经准入的历史首页目标，不创建虚构访问、目标更新或候选列表。项目、自定义 GPT、账户/工作区查询和未支持路由保留精确身份；不把任意同站点页面都视为可互换。未登记过且没有历史证据的入口不从后台扫描获得。

用户明确要求重置行为数据时，必须先正常停止采集并确认数据库连接关闭，再将指定数据库及其仍存在的 WAL／SHM 和指定标准导出快照移入废纸篓。身份密钥、已登记目标与偏好独立保留。重置是显式的一次性维护操作，不是应用启动或策略升级时自动执行的迁移。

2026-09-18 已按用户要求重置全部旧行为库与现有标准导出。上方 v1 路径是兼容位置，不表示重置后仍存在该文件；恢复位置与验收限制见 [目标准入验收](TARGET_ELIGIBILITY_VALIDATION.md)。

- 应用数据根目录与导出目录使用 `0700`，应用创建的数据库、密钥、登记信息和导出文件使用 `0600`。SQLite 的 `-wal` / `-shm` 可能显示其他文件模式，访问仍受 `0700` 父目录限制；由 SQLite 管理这些文件，不手动删除。
- 读取活动数据库时使用 SQLite 连接和快照事务；不要把正在写入的 `.sqlite` 文件单独复制后当作完整备份。统计、历史读取和导出使用独立只读连接，不能占用串行写入队列。备份功能应使用 SQLite 在线备份 API，或确认所有连接关闭后备份完整状态。
- 恢复页面身份需要匹配的 `identity-v2.key`，有登记目标时还需要 `registered-targets.json`。密钥不进入训练导出、版本控制或共享数据包。JSONL 导出是训练快照，不是应用完整恢复备份。
- 原始记录与训练用的五分钟/一小时历史窗口相互独立；不因模型窗口较短而删除旧记录。当前没有自动归档或清理，达到容量上限会暂停采集，后续保留/清理策略需明确实现。
- 数据目录迁移必须先形成可验证备份，暂停旧路径写入，核对记录数量、身份密钥与权限，再切换读写入口；禁止在应用仍连接旧路径时直接移动数据库。文档、应用、CLI 和导出脚本的默认路径需同步更新。
- 不将用户行为日志提交到源码仓库；仓库内必要的测试数据必须为合成数据。临时验收导出可以留在 `/tmp`，但不可把它当作长期归档位置。

登录后自动采集的独立同意保存为 `UserDefaults.collectOnLoginV1`（默认 false），不写入行为库。它不替代系统登录项授权，也不使普通手动启动自动采集。
