# 动态菜单接入验证

日期：2026-10-10。范围：当前在线模型与分差算法的接入、状态保存与菜单布局。数据全部为合成测试行为，不读取个人行为库。

## 用户确认的行为

- 漏选调整目标 10%，尚未测得个人行为下的实际漏选率。
- 显示数量动态变化，暂时最多 6 项；没有最低数量，不补齐到 4 项。
- 首项位于鼠标右上方，后续按固定 60° 间距顺时针展开。选项少时只占一段圆弧。
- 原排序模型继续运行；新模块只调整分差门槛和数量，不是另一套预测模型。

## 接入与保存

`FastRecommendationService` 保留原模型的具体分数，在每次合法前台到达时冻结预测。新确认的成熟后续行为用 `OnlinePathInputHistory.usefulActionIndices` 判断具体目标或合法上级；冻结时没有正确入口的行为仍计入分母。分差门槛和六项上限的覆盖分别计数，不把第七项当作已展示。

`RecorderModel` 沿用已确认的历史目标及其临时推导上级，先核对资格和执行入口，再应用门槛与六项上限。菜单只读当前状态；唤出、展示、关闭不发出学习预测，不持久化候选清单。选择后的确认到达仍走原反馈流程。

校准只保存排序分差、版本、参数和汇总，随当前模型权重在同一次原子写入中保存；不保存候选、预测或结果身份。旧权重可从无校准样本启动；坏校准保留有效排序模型并报告重置原因。冻结预测的时间检查使用数据库全局序号，重启不重算过去的分数。

- 日志保存在 `build/dynamic-menu-tests.log`、`build/dynamic-menu-release-build.log`。

一次重跑暴露了旧模型兼容检查直接比较小数全值的问题：恢复前后同一目标相差约 `1e-16`，目标及排序一致。该检查改为同时核对目标集合、排序和 `1e-12` 内的数值一致；没有改旧模型计算或运行流程。最终结果以修正后的完整检查为准。

关键检查包括：门槛只保留一个目标时实际菜单也只显示一个；重复读取菜单不学习；关闭菜单不写入菜单数据；正确入口在第七位时单独记为上限漏选；未知结果不学习；模型和校准重启恢复不重复学习；连续提交不漏处理；右上起点和顺时针位置保持固定；六个点击区域互不重叠并留在面板内；屏幕边缘及小屏避让。

原生视图预览使用合成目标及系统应用图标，位于 `build/menu-previews/menu-1.png`、`menu-3.png` 和 `menu-6.png`。图示用于核对位置、数量、图标及文字，玻璃材质的最终合成取决于实际窗口环境；这些不是已安装应用的截图。
